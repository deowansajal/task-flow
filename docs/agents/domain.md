# Domain docs

## Layout

This repo uses a single-context layout:

- `GLOSSARY.md` at the repo root.
- Architecture decision records in `docs/adr/`.

## Before exploring

Read the glossary and ADRs relevant to the work.
If they do not exist, proceed silently.
Create domain documentation lazily when terms or decisions
are resolved through domain modeling.

## Vocabulary

Use glossary terms when naming domain concepts in issues,
proposals, hypotheses, and tests.

If a needed concept is missing, reconsider the term or
note the gap for domain modeling.

## Decision conflicts

Explicitly identify any proposal that contradicts an ADR,
including the ADR reference and reason to reconsider it.
